# Запуск и совместная работа

## Запуск на этом ноутбуке

Открой папку StudyFlow в VS Code. В терминале выполни:

```powershell
cd "$env:USERPROFILE\Documents\Codex\StudyFlow"
dotnet restore StudyFlow.sln
dotnet run --project src/StudyFlow.Web
```

Открой **http://localhost:5188**. Терминал должен оставаться открытым. Чтобы остановить приложение, нажми `Ctrl+C`. Нужен .NET 8 SDK.

Если порт занят:

```powershell
dotnet run --project src/StudyFlow.Web --urls http://localhost:5190
```

Тогда открой http://localhost:5190.

## Что открыть

- **My tasks** — задачи, сроки, поиск, фильтры и отметка выполнения.
- **Subjects** — предметы, их названия и цвета.
- **Study planner** — доступное время по дням недели и план.
- **Progress** — выполненные и оставшиеся задачи, оценки времени, результаты по предметам.

Сначала добавь предмет и задачу. Затем сохрани время на странице планировщика и нажми **Generate plan**. Если задача не помещается до срока, программа покажет оставшиеся минуты и причину.

## Проект на другом компьютере

```powershell
git clone https://github.com/Eralyy/StudyFlow.git
cd StudyFlow
dotnet restore StudyFlow.sln
dotnet run --project src/StudyFlow.Web
```

GitHub хранит код. Личная база не загружается в репозиторий, поэтому новая копия проекта начинает с пустого списка. База создаётся автоматически.

Файл с данными: `src/StudyFlow.Web/App_Data/studyflow.db`. Для резервной копии останови приложение и скопируй этот файл. В нём хранятся задачи, предметы и доступное время. План рассчитывается заново.

## Проверки перед изменениями

```powershell
dotnet build StudyFlow.sln
dotnet test StudyFlow.sln
```

Для проверок в браузере нужен Node.js 20 или новее:

```powershell
npm ci
npx playwright install chromium
npm run test:e2e
```

Тесты создают временные базы и не очищают обычные данные.

## Работа вдвоём через GitHub

Основная версия находится в `main`. Для следующего изменения сначала проверь `git status`: чужие незавершённые изменения нельзя перезаписывать. Создай отдельную ветку:

```powershell
git fetch origin
git switch main
git pull --ff-only origin main
git switch -c feature/your-change
```

После небольшой законченной правки запусти тесты, добавь только изменённые файлы, сделай коммит и Pull Request. Второй участник проверяет изменение до объединения.

Аккаунт GitHub и имя автора коммита — разные настройки. На общем ноутбуке перед коммитом проверь `git config user.name` и `git config user.email`. Используй реальные данные того, кто сейчас делает изменение. Не переписывай старые коммиты ради разделения ролей.

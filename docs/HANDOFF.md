# Продолжение проекта на одном ноутбуке

## Запуск текущей части

Открой папку `StudyFlow` в VS Code. На этом ноутбуке она находится здесь:

```powershell
cd "$env:USERPROFILE\Documents\Codex\StudyFlow"
dotnet restore StudyFlow.sln
dotnet build StudyFlow.sln
dotnet test StudyFlow.sln
dotnet run --project src/StudyFlow.Web --urls http://127.0.0.1:5188
```

Открой `http://127.0.0.1:5188` в браузере. Оставь терминал открытым; `Ctrl+C` останавливает приложение. Для запуска нужен .NET 8 SDK.

GitHub хранит код. Локальная база данных не загружается в репозиторий: у отдельной копии проекта будут свои данные.

По умолчанию база находится в `src/StudyFlow.Web/App_Data/studyflow.db`. При запуске применяются миграции для создания нужных таблиц. Демонстрационные данные добавляются отдельной кнопкой, когда задач ещё нет; они не подменяют уже сохранённую работу.

## Получение проекта на другом компьютере

Первая часть опубликована в основной ветке `main`:

```powershell
git clone https://github.com/Eralyy/StudyFlow.git
cd StudyFlow
dotnet restore StudyFlow.sln
dotnet run --project src/StudyFlow.Web --urls http://127.0.0.1:5188
```

## Ветка напарницы

Сначала владелец репозитория добавляет `aknur-g` в collaborators, а напарница принимает приглашение. Перед сменой ветки выполни `git status`: незавершённые изменения первого участника нужно сохранить, не перезаписывая их.

Новая ветка создаётся от готовой первой части в `main`:

```powershell
git fetch origin
git switch main
git pull --ff-only origin main
git switch -c feature/study-planner
```

Вход в GitHub и авторство коммитов — разные настройки. Напарница входит в GitHub под своим аккаунтом, а затем задаёт настоящие имя и подтверждённый GitHub email для этого репозитория:

```powershell
git config --local user.name "ИМЯ НАПАРНИЦЫ"
git config --local user.email "ЕЁ EMAIL ИЗ НАСТРОЕК GITHUB"
```

Перед запуском замени текст в кавычках реальными значениями. Настройка применяется только к последующим коммитам; историю первой части переписывать не нужно. При возвращении первого участника следует снова установить его имя и email.

После реализации законченной функции:

```powershell
dotnet test StudyFlow.sln
git status
git add ПУТИ_К_ИЗМЕНЁННЫМ_ФАЙЛАМ
git commit -m "Add available study time settings"
git push -u origin feature/study-planner
```

В `git add` укажи фактически изменённые файлы. Затем создай Pull Request в GitHub. Первый участник проверяет изменения и запускает тесты. Перед объединением ветки планировщика убедитесь, что `main` уже содержит первую часть.

## Что должна сделать напарница

Добавить настройку доступного времени, чистую функцию распределения задач, предупреждения о нехватке времени и статистику. Общие модели и правила описаны в `PLAN.md`. Не нужно заново создавать предметы, задачи или отдельную копию базы внутри проекта.

Перед защитой оба участника проходят сценарий из `DEFENCE.md` и затем аналогичный сценарий планирования. Разделение разработки не отменяет необходимости понимать приложение целиком.
